# AGENTS.md

Docusaurus 3.10 documentation site for CTX CLI, deployed to GitHub Pages at
`ctx.mohantyabhisek.com`. Markdown/MDX under `docs/` is the only canonical
content; never edit `build/` or `.docusaurus/` (both generated and gitignored).

## Working rules

- Never commit, push, merge, or open a PR unless the user explicitly asks in
  that turn. Do not commit proactively.
- When asked to commit, present the draft message first and wait for approval.
- Never run `sudo`, `su`, `doas`, or `pkexec`. Show the exact command so the
  user can run it themselves.
- Ask before installing packages, dependencies, or tools.

## Commands

- `npm install` locally, or `npm ci` for the exact lockfile (CI uses Node 22).
- `npm run start` — dev server. It does not catch broken links.
- `npm run build` — the real verification. `onBrokenLinks: "throw"` makes bad
  internal links fail the build. Also generates `build/llms.txt`,
  `build/llms-full.txt`, and a `.md` mirror of every docs page.
- `npm run serve` — serve the last production build.
- `npm run typecheck` — standalone `tsc`; the Docusaurus build does not
  typecheck. Run it after editing `.ts`, `.tsx`, or config files.
- `npm run clear` — clear the `.docusaurus` cache when builds look stale.

There are no test or lint scripts. `.markdownlint.yaml` exists but is not wired
into npm or CI. CI runs only `npm ci` + `npm run build` (despite the README
diagram mentioning a type-check step).

## Documentation layout and conventions

- Pages are folder-per-page: `docs/<section>/<page>/index.md` (or `index.mdx`
  when JSX/imports are needed). Section landing pages are also `index.md`.
- The sidebar is autogenerated from the `docs/` tree (`sidebars.ts`); do not
  maintain sidebar item lists. Order pages with `sidebar_position` front
  matter. Doc labels come from the title/front matter (or `sidebar_label`);
  category labels come from folder names.
- Files matching `_*.md` / `_*.mdx` are excluded from the build. Reusable
  templates live at `docs/commands/_template.md`, `docs/workflows/_template.md`,
  and `docs/workflows/guides/_template.md`; follow the relevant template when
  adding a command, workflow, or workflow guide. HTML comments in them are
  authoring notes and do not render.
- Command pages: H1 is the full command (`# ctx task create`), then an H2 with
  the command name/alias, Arguments/Options tables, subcommand links written as
  `./child/`, then `What it does`, `When to use it`, `How it works`, `Examples`.
- Use relative internal links with a trailing slash, e.g.
  `../../../../internals/identifier/`. The production build rejects broken
  links.
- Blog posts belong in `articles/` (the blog path is overridden from `blog/` to
  `articles/` in `docusaurus.config.ts`); `articles/` is currently empty.

## Agent skills

- Shared skills live in `.agents/skills/` and are used by both OpenCode and
  VS Code Copilot. Do not create a duplicate `.github/skills/` tree.
- Install or inspect them with `npx skills ...`; `skills-lock.json` records the
  upstream sources. Run `npx skills list` to see the installed set.

## Writing and architecture references

- Read `WRITING_GUIDE.md` before substantive prose changes; it defines the
  brand voice, terminology, command-reference wording, and error-message style.
  However skills take priority.
- `README.md` explains the site architecture, SEO, search, AI-readable output,
  branching, and deployment. `DOCUMENTATION_VERSIONING_STRATEGY.md` is the
  versioning policy.
- Prefer these existing files over duplicating their rules in a new doc.

## Versioning

- `docs/` is the current documentation. There is no `versions.json`,
  `versioned_docs/`, or `versioned_sidebars/` yet, so the version dropdown only
  shows `Next`. In practice `docs/` is deployed directly from `main`; the
  strategy document's "development docs stay internal" step is not implemented.
- Snapshot a release with `npm run docusaurus docs:version <version>` (for
  example `1.0.0`). That creates the versioned docs/sidebar files and updates
  `versions.json`.
- Released snapshots must not be rewritten to describe newer CLI behavior;
  continue changes in `docs/` and create the next snapshot at release time.

## Git and deployment

- Commits are not Conventional Commits. Use section headers `Feature:`,
  `Refactor:`, `Fix:`, `Test:`, `Todo:`, and `Docs:`, each followed by
  past-tense bullets such as `- Updated ...`. See
  `.vscode/copilot/commit-message.md`.
- PRs and pushes to `main` run CI. A successful `main` build is deployed to
  GitHub Pages by `.github/workflows/deploy.yml`; keep `static/CNAME` intact.
- `.env` is gitignored and contains live API tokens. Do not print, commit, or
  copy its contents.
